## A. Сегментация изображений

### Текущее состояние OpenRebar

Модуль `ml/` реализует классический U-Net на PyTorch. Входное изображение —
plan-view PNG с ΔE*76 цветовым матчингом для разбиения изолиний по зонам
(см. README: «PNG path is described as exact RGB matching»). Точность на
синтетике не заявлена (нет корпуса). Экспорт в ONNX для инференса в C# готов.

### SOTA 2026

#### SAM2 — Segment Anything Model 2 (Meta / ICLR 2025)

- **Ссылка:** https://github.com/facebookresearch/sam2
- **Вклад:** Foundation model для сегментации изображений **и видео** с promptable
  интерфейсом (клик, bbox, маска). Оценён на 37 zero-shot датасетах.
  1-click mIoU сильно превосходит SAM v1 на object segmentation.
- **Применимость к OpenRebar:** Zero-shot, без fine-tuning, способен выделять
  зоны армирования по одному клику инженера. Заменяет ручную калибровку
  `--px-per-mm` — пользователь просто кликает на угол плиты.
- **Ограничение:** Модель 308 MB (ViT-B) — 2.4 GB (ViT-H). Офлайн-деплой
  возможен, но требует GPU ≥8 GB VRAM для Hiera-L. CPU-инференс в 3–10×
  медленнее чем current U-Net.

#### EoMT / LUMA — «Your ViT is Secretly an Image Segmentation Model» (CVPR 2025)

- **Ссылка:** https://openaccess.thecvf.com/content/CVPR2025/papers/Kerssies_Your_ViT_is_Secretly_an_Image_Segmentation_Model_CVPR_2025_paper.pdf
- **Вклад:** ViT-L (DINOv2) без адаптера достигает **84.5 mIoU на ADE20K**
  при 150 FPS на 512×512; LUMA (2026) показывает 58.9 mIoU ADE20K
  (semantic segmentation benchmark класса SOTA).
- **Применимость:** DINOv2 features сильны на domain shift — план-чертёж
  vs. реальная фотография. Подходит для классификации зон по типу армирования
  (фон/дополнительное/верх/низ).

#### YOLOv11 + SAM двухэтапная модель (MDPI 2026)

- **Ссылка:** https://www.mdpi.com/2075-5309/16/4/794
- **Метрики:** Accuracy 95.98%, Precision 92.60%, IoU **0.77** для трещин
  на бетоне (без re-tuning на арматурный чертёж).
- **Применимость:** Трещины в бетоне — смежная область. Два этапа:
  MEP-YOLOv11 детектирует объекты → SAM доуточняет маску. Аналог
  для OpenRebar: YOLOv11 детектирует зоны → SAM по bbox выделяет полигон.

#### SECrackSeg + UNet+SAM (PMC 2025, 17 citations)

- Интеграция SAM как вспомогательного декодера в U-Net улучшает mIoU
  трещин на 4–6 пп. без дополнительной разметки.

### Gap-анализ и дорожная карта для OpenRebar

| Шаг | Действие | Сложность | Эффект |
|-----|----------|-----------|--------|
| ML-A1 | Заменить U-Net backbone на DINOv2 ViT-S (22 M params) | Medium | +10–15 mIoU |
| ML-A2 | Добавить SAM2-prompt: пользователь кликает на 2 угла плиты | Medium | Замена `--px-per-mm` |
| ML-A3 | Собрать 50+ аннотированных планов (синтетика + реал) через Label Studio | High | Даёт объективный benchmark |
| ML-A4 | Экспортировать DINOv2+head в ONNX int8, замерить CPU latency | Low | Подтвердить офлайн-пригодность |

**Вывод:** Current U-Net — это 2022-уровень. SAM2 zero-shot прямо сейчас даёт
lучшую точность без разметки. Приоритет: ML-A2 (prompt interface) для UX,
ML-A1 для качества.

## B. Оптимизация раскладки арматуры (GNN)

### Текущее состояние OpenRebar

Раскладка детерминированная: зональная сетка, равномерный шаг, дополнительные
стержни между фоновыми. Нет машинного обучения в контуре раскладки.
Algorithmically sound, но не оптимальна по массе/конструктивности.

### SOTA 2026

#### GNN + EGA (Automated. Constr. 2023, 56 citations)

- **Ссылка:** https://www.sciencedirect.com/science/article/pii/S0926580522005477
- **Авторы:** Li, Liu et al.
- **Вклад:** Graph Neural Network кодирует топологию арматурного решения
  (узлы = стержни, рёбра = стыки/пересечения). Exploratory Genetic Algorithm
  (EGA) использует GNN как surrogate cost function для оценки
  конструктивности. Сходимость в 10× быстрее чем чистый EA.
- **Применимость к OpenRebar:** GNN может заменить простую сеточную
  эвристику. Узлы графа = зоны армирования, рёбра = нахлёсты и пересечения.

#### DfMA-GNN (ASCE J. Computing 2026)

- **Ссылка:** https://ascelibrary.org/doi/abs/10.1061/JCCEE5.CPENG-7477
- **Вклад:** «Design for Manufacture and Assembly»-ориентированная оптимизация
  плит: GNN + метаэвристика для баланса structural performance / material
  efficiency / constructability. Достигает −12% масса стали vs. ручного
  проектирования на RC плитах.
- **Применимость:** Прямая — RC slab, тот же класс задачи.

#### PIGNN — Physics-Informed GNN (ScienceDirect 2026)

- **Ссылка:** https://www.sciencedirect.com/science/article/abs/pii/S0926580526000014
- **Вклад:** Constructability-aware PIGNN для оптимизации рабочей арматуры
  балок. Physics constraints (прочность, расход) встроены в функцию потерь
  GNN как soft constraints. Surrogate model ускоряет оценку в 200× vs. FEM.
- **Применимость:** Плиты — расширение от балок. Ввод: As-карта (уже есть
  как CSV/PNG isoline), выход: оптимальная топология.

#### DRL для стен (Soft Actor-Critic, ScienceDirect 2026)

- **Ссылка:** https://www.sciencedirect.com/science/article/abs/pii/S0141029626001859
- **Вклад:** SAC agent обучается раскладывать арматуру стен (дискретный + непрерывный action space). Reward = прочность − масса − стоимость.
- Достигает Pareto-front за 500 эпизодов на GPU V100.

#### 2-stage ANN+DRL для RC балок (Nature Sci Reports 2026)

- **Ссылка:** https://www.nature.com/articles/s41598-025-18543-4
- **Вклад:** ANN предсказывает начальное решение (surrogate), DRL доводит
  до оптимума. Low-carbon objective: минимизация CO₂ при As ≥ As,req.
- Снижение CO₂ на 18% vs. code-minimum.

### Gap-анализ и дорожная карта для OpenRebar

| Шаг | Действие | Сложность | Эффект |
|-----|----------|-----------|--------|
| GNN-B1 | Формализовать граф зон: узлы=зоны, рёбра=смежность/нахлёст | Low | Основа для GNN |
| GNN-B2 | Surrogate GNN для оценки Δмасса/Δстыки без полного pipeline | High | Ускорение оптимизации |
| GNN-B3 | DRL (SAC) для выбора шага и диаметра доп. стержней | Very High | −10–15% масса при As≥As,req |
| GNN-B4 | PIGNN physics loss: As,prov ≥ As,req как дифференцируемое ограничение | Very High | Convergence guarantee |

**Вывод:** GNN — следующий крупный технический скачок для OpenRebar (P3).
Prerequisite: наличие реального датасета планов. Без датасета GNN не обучить.
Первый шаг — GNN-B1 (формализация графа) можно сделать уже сейчас как
структуру данных в Domain, без ML.

## C. Задача раскроя (1D CSP / Bin Packing)

### Текущее состояние OpenRebar

Column Generation (HiGHS LP) + FFD fallback. Детерминированный, точный
для малых и средних инстанций. 27% отходов на simple-slab — не вина солвера
(RT-4 в r9: рычаг — joint co-optimization).

### SOTA 2026

#### DRL-CSP: Pointer Network + Model-Free RL (MDPI Mathematics, 2023, 33 citations)

- **Ссылка:** https://www.mdpi.com/2227-7390/11/4/1028
- **Авторы:** Fang et al.
- **Вклад:** Pointer Network с LSTM encoder-decoder как policy network;
  обучение model-free RL. На 82 из 3 датасетов получает 
appoximate optimal в 10× быстрее exact solver для n>500 штук.
- **Применимость:** При n<100 позиций (типичный план) Column Generation
  уже близко к оптимуму. DRL-CSP выгоден при n>200 позиций или при
  онлайн-реоптимизации в реальном времени.

#### A2C + Pointer Network для 1D-BPP (Nature Sci Reports, 2026)

- **Ссылка:** https://www.nature.com/articles/s41598-026-63499-8
- **Вклад:** Advantage Actor-Critic + Pointer Network с LSTM. Оптимизирует
  **порядок укладки** изделий в bin, не только разбиение. На конвейерной
  логистике: +7.3% загрузка vs. First Fit Decreasing.
- **Применимость:** FFD → A2C-BPP для рулонов арматуры. Снижает количество
  отходных хвостов при общем стоке 12 м.

#### RL for Benders Decomposition (arXiv 2026)

- **Ссылка:** https://arxiv.org/pdf/2605.06516
- **Вклад:** RL обучает классификатор cuts для Benders Decomposition —
  отбирает cuts, ускоряющие сходимость мастер-задачи. Совместимо с HiGHS.
- **Применимость:** Column Generation в OpenRebar — частный случай BD.
  RL-cut selector может сократить число итераций CG для крупных планов.

### Gap-анализ и дорожная карта для OpenRebar

| Шаг | Действие | Сложность | Эффект |
|-----|----------|-----------|--------|
| CSP-C1 | RT-4: вывести оба KPI (% отходов + стоимость закупки) в report | Low | Честная метрика |
| CSP-C2 | PR-17: BFD-v1 как 3-й fallback (MinScrapLengthMm) | Low | −3–5% отходов |
| CSP-C3 | Joint optimization: передать lap positions в CG как дополнительные переменные | Medium | Потенциал −11% закупка (RT-4) |
| CSP-C4 | DRL-CSP: pointer network для онлайн-реоптимизации при n>200 | High | Speed + quality для крупных объектов |

**Вывод:** Column Generation — уже хороший уровень (лучше рынка). Ближайший
прагматичный шаг — CSP-C3 (joint optimization), описанный в RT-4.

## D. IFC / открытый BIM

### Текущее состояние OpenRebar

IFC4 export через xBIM Essentials: `IfcReinforcingBar`, прямолинейные тела
(`IfcSweptDiskSolid`). PR-10 запланирован: `IfcReinforcingBarType`, correct
placement, IDS validation в CI.

### SOTA 2026

#### IFC 4.3.2.0 (IFC4X3_ADD2) — официальный стандарт

- **Ссылка:** https://standards.buildingsmart.org/IFC/RELEASE/IFC4_3/index.html
- **Статус:** Official ISO standard. ADD2 — второй аддендум, закрыл
  большинство дыр в bridge reinforcement schema.
- **Ключевые изменения для арматуры:**
  - `IfcReinforcingElement` расширен: `IfcTendon`, `IfcTendonAnchor`,
    `IfcReinforcingMesh` — полная модель.
  - `IfcReinforcingBar`: атрибут `BarSurface` (PLAIN/TEXTURED), `CrossSectionArea`.
  - Lap splice encoding: `IfcReinforcingBarType` → `IfcReinforcingBarSpliceType`.
  - `IfcApproval` для нормативного соответствия — прямой аналог нашего
    `result.json` contract.
- **Дискуссии buildingSMART (март 2026):** «ReinforcingBar Lap Lengths» —
  активное обсуждение как корректно кодировать нахлёст в IFC4.3.
  Field bent rebar (гнутые стержни) — отдельный thread.

#### IDS (Information Delivery Specification) — SOTA для CI

- IDS v1.0 (buildingSMART, 2025) — машинно-читаемая спецификация требований
  к IFC-модели. Позволяет автоматически проверять: «все `IfcReinforcingBar`
  должны иметь `BarSurface`; все балки должны содержать `IfcReinforcingMesh`».
- **Применимость:** Добавить IDS-файл `openrebar.ids` и валидацию в CI
  (PR-10). Тест не просто хэш, а семантическая проверка.

#### Allplan 2026 — SOTA коммерческий BIM

- **Ссылка:** https://aecmag.com/bim/allplan-unveils-2026-products/
- **Возможности:** Automated column reinforcement design; single-click
  horizontal/vertical wall reinforcement; deactivation of hidden reinforcement
  categories in plan creation.
- **Импликация для позиционирования OpenRebar:** Allplan 2026 закрывает
  column и wall automation. OpenRebar должен фокусироваться на **плитах**
  (slabs) с FE-driven As-картой — там Allplan слабее.

#### MA-REBARS 2026 (Revit extension)

- **Ссылка:** https://marketplace.autodesk.com/apps/d0bff47a-6adc-4d80-878a-ca18bb5b653f
- Parametric rebar automation + smart view tools. Не open-source.
- Подтверждает: Revit plugin market активен, есть спрос.

### Gap-анализ и дорожная карта для OpenRebar

| Шаг | Действие | Сложность | Эффект |
|-----|----------|-----------|--------|
| IFC-D1 | PR-10: upgrade до IFC4 proper (IfcReinforcingBarType, placement, IfcSweptDiskSolid no inner) | Medium | Совместимость с IFC-viewers |
| IFC-D2 | IDS validation: openrebar.ids + mvd-check в CI для каждого Export/ PR | Medium | Автоматическая semantic check |
| IFC-D3 | Изучить IFC4.3 lap splice encoding, добавить IfcReinforcingBarSpliceType | High | Полный обмен нахлёстами |
| IFC-D4 | Тест против Revit IFC importer: проверить roundtrip IfcReinforcingBar | High | Заявить «Revit-compatible IFC» |

**Вывод:** PR-10 — правильный следующий шаг. IFC4.3 — цель после PR-10.

## E. Нормативная автоматизация (LLM + AI compliance)

### Текущее состояние OpenRebar

СП 63.13330.2018 с Изм. 1 жёстко зашит в таблицы JSON
(`ru.sp63.2018.tables.v3.json`). Расчёты детерминированные, traceability
документируется в `NORMATIVE_TRACEABILITY.md`. Нет LLM, нет natural language
interface к нормам.

### SOTA 2026

#### Multi-agent LLM Framework для RC design (ResearchGate 2026)

- **Ссылка:** https://www.researchgate.net/publication/394393279
- **Вклад:** Несколько LLM-агентов с разными специализациями (loads,
  geometry, reinforcement, code-check) координируются через orchestrator.
  Каждый агент читает соответствующий раздел кода (Eurocode 2) и выдаёт
  structured output. Точность на простых RC балках: 89% vs. ручного расчёта.
- **Применимость:** Automated interpretation of СП 63 (Amendment 1 → Amendment 2
  не вышел, но можно готовиться). LLM-агент для `stop questions` (Rbt
  B55/B60, Rsc A400).

#### LLM-driven BIM Code Compliance (arXiv 2506.20551, 84 citations)

- **Ссылка:** https://arxiv.org/abs/2506.20551
- **Авторы:** Madireddy et al. (University of Houston)
- **Вклад:** GPT-4 / Claude / Gemini интегрированы с Revit. LLM читает
  building code, генерирует Python скрипт проверки, запускает его через
  Revit API. Semi-automated: ~70% кода генерируется без правок.
- **Применимость:** Аналог для OpenRebar: LLM читает СП 63 clause, пишет
  Python-валидатор → `tools/verify/hand_checks.py` становится LLM-generated.

#### Python Eurocode Automated Framework (MDPI Buildings 2026)

- **Ссылка:** https://www.mdpi.com/2075-5309/16/19/3813
- **Вклад:** Python-based parametric framework: geometry → FEM (OpenSeesPy) →
  Eurocode load combinations → reinforcement check. Полностью автоматизированный
  pipeline от геометрии до сертификата соответствия.
- **Применимость:** Подход совместим с OpenRebar: заменить ручной FE-импорт
  на автоматическую генерацию из геометрии плиты.

#### SEI Structures Congress 2026: AI in Structural Engineering

- **Ссылка:** https://pesengineers.com/sei-structures-congress-2026
- Консенсус: LLM → code compliance starting point, не замена инженера.
  «Most accessible starting point: LLM the firm already has access to».
- Bias warning: LLM hallucinate нормы, особенно региональные (ГОСТ, СП).
  Нужна retrieval-augmented generation (RAG) с оригинальным текстом нормы.

### Gap-анализ и дорожная карта для OpenRebar

| Шаг | Действие | Сложность | Эффект |
|-----|----------|-----------|--------|
| LLM-E1 | RAG-индекс СП 63 (PDF → chunks → embeddings) для stop-question lookup | Medium | Ответы на вопросы владельца |
| LLM-E2 | LLM-agent для генерации Python-валидатора из текста нормы (proof of concept) | High | Автоматизация `hand_checks.py` |
| LLM-E3 | Проверить LLM-generated Rbt B55/B60 против первоисточника (RT-3) | Low | Ответ на стоп-вопрос |
| LLM-E4 | IfcApproval: записать result.json → IFC normative approval record | Medium | Audit trail в BIM |

**Вывод:** LLM для стоп-вопросов (LLM-E3) — низкая сложность, высокий эффект.
RAG-индекс — следующий шаг после наличия текста нормы.

## F. Физически-обоснованные модели (PINN / DRL)

### Текущее состояние OpenRebar

Нет PINN, нет DRL в инженерном расчёте. Трещиностойкость и прогибы —
`NotEvaluated` (честно, корректно для текущего input-only-As режима).

### SOTA 2026

#### PINN для RC балок (РАН/Springer 2026)

- **Ссылка:** https://link.springer.com/article/10.1007/s00366-026-02375-5
- **Вклад:** PINN для балок (Euler-Bernoulli + Timoshenko) с аналитическими
  решениями как hard constraints в loss. Точность прогибов: <1% ошибка.
  Hyperparameter sensitivity тщательно изучена.
- **Применимость:** Для плит: добавить `deflectionCheck: PINN` mode
  (NotEvaluated → Approximated). Требует только геометрию + нагрузки.

#### Interpretable PINN для сдвигостойкости RC балок (ScienceDirect 2026)

- **Ссылка:** https://www.sciencedirect.com/science/article/pii/S2666165926001997
- **Вклад:** Multi-branch PINN с явной связью физических переменных
  (As, bw, d, ρ, fc) и прочности на сдвиг. Interpretable — каждая ветвь
  соответствует члену СНиПовской формулы.

#### SAC для проектирования стен (ScienceDirect 2026)

- Soft Actor-Critic (SAC) — off-policy RL с entropy maximization.
  Convergence в 500 эпизодов для дискретно-непрерывного action space
  (диаметр + шаг + зона).
- Для плит: action = {d, s, zone_boundary}, reward = −mass − penalty_As_deficiency.

### Gap-анализ и дорожная карта для OpenRebar

| Шаг | Действие | Сложность | Эффект |
|-----|----------|-----------|--------|
| PINN-F1 | PINN-surrogate для прогибов (Timoshenko): `deflectionStatus: Approximated` | High | Первый инженерный check |
| PINN-F2 | PINN для трещиностойкости по СП 63 п. 8.1–8.3 | Very High | Закрыть `crackWidthStatus: NotEvaluated` |
| DRL-F3 | SAC agent для выбора d/s: offline training, online inference | Very High | Оптимизация As при ограничениях |

**Вывод:** PINN — долгосрочная P3 цель. Prerequisite: реальные нагрузки
(сейчас только As-поле). Немедленно реализовать нельзя без расчётной схемы.

## Честное позиционирование OpenRebar vs. SOTA 2026

| Критерий | OpenRebar | SOTA лидер | Разрыв |
|----------|-----------|-----------|--------|
| Открытость | ✅ MIT, офлайн | Закрытые (Allplan, MA-REBARS) | OpenRebar выигрывает |
| Нормативный провенанс | ✅ traceability.md, parameterSources | Нет у конкурентов | OpenRebar выигрывает |
| Сертификат As,prov ≥ As,req | ✅ per-cell, polygon deficit | Нет открытого аналога | OpenRebar выигрывает |
| Раскрой + нахлёсты | ✅ Column Generation + laps | FFD у Tekla, нет у open tools | OpenRebar выигрывает |
| ML segmentation quality | ⚠️ базовый U-Net | SAM2 / DINOv2 | OpenRebar отстаёт |
| Layout optimization | ❌ нет GNN/DRL | PIGNN, DfMA-GNN | Большой разрыв |
| IFC версия | ⚠️ IFC4 basic | IFC4.3.2.0 ADD2 | Умеренный разрыв |
| Трещиностойкость/прогибы | ❌ NotEvaluated | PINN (2026) | Разрыв, приемлемо для As-only tool |
| LLM compliance | ❌ нет | Multi-agent LLM (2026) | Разрыв, P3 приоритет |

**Вывод:** OpenRebar имеет устойчивые конкурентные преимущества в открытости,
провенансе и честных статусах (`Failed` не маскируется). Главный tech debt —
ML качество и отсутствие layout optimization. Эти разрывы закрываются в P2–P3.
