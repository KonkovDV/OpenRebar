## 2. Новые находки Red Team (в прошлых аудитах их нет)

**RT-1 (S0). Торцевой защитный слой = 0.** `coverEdgeMm` по умолчанию 0: в эталоне `simple-slab` стержни идут от x=0 до x=6000, то есть ось стержня на грани плиты, а крюки (2×282,7 мм дуги) физически вне бетона. Исправить: рабочая область по свободному краю = `max(coverEdgeMm, coverMm + d/2)`; при `coverEdgeMm < coverMm` — предупреждение `EdgeCoverBelowCover`. Ожидаемое: пролёт 5940 мм вместо 6000, длина 6505,5 мм, масса 27×6,5055×2,47 = 433,85 кг. Эталоны перегенерировать `tools/examples/generate_expected_outputs.*`, каждую цифру объяснить в PR.

**RT-2. PR-5 из AGENT_PLAN «шаг > max = ошибка» неверен для дополнительных зон.** Доп. стержни ставятся между фоновыми, их собственный шаг законно больше 10.3.8. Проверять максимальный шаг по **суммарному** слою (фон + доп.) в `ClearanceChecker`/верификаторе, не в калькуляторе зоны.

**RT-3. Rbt для B55/B60.** В таблице 1,65/1,70 МПа; по табл. 6.8 СП 63 (Rbt,n/γbt = 2,60/1,5 и 2,75/1,5) ожидается 1,70/1,80. Ошибка в запас (анкеровка длиннее). Не менять без первоисточника: стоп-вопрос владельцу, приложить скан табл. 6.8.

**RT-4. 27% отходов на эталоне — не вина солвера.** Изделие 6565 мм при каталоге 6000/9000/11700/12000 оптимально режется 1 шт./9000 мм. Рычаг — совместная оптимизация стыков и раскроя (F4): 2 куска с нахлёстом по ≈3780 мм дают 3 шт. из 12000, закупка 216 м вместо 243 м (−11%), но уложено +15% стали. Решение принимать по стоимости, а не по % отходов: выводить оба KPI.

**RT-5. Доля стыков считается по группе с одинаковыми концами**, а не по всему сечению слоя. Соседние группы с другими концами не входят в знаменатель. Перенести расчёт доли в `ClearanceChecker` по всем стержням слоя в окне 1,3·l_l (он уже так делает для `lapOverload`) и сделать его источником истины для α.

**RT-6. Модель нахлёста.** Куски коллинеарны (N-5). Проверка r9 предполагает контактный нахлёст шириной 2d, центрированный на линии. Ввести `laps.representation` (inPlane/stacked) и сдвиг второго куска на d в IFC/Revit, иначе тела пересекаются.

## 5. Позиционирование для жюри (без преувеличений)

«Фон + дополнительное» есть у САПФИР-ЖБК, TSD, SAFE, RFEM, SOFiSTiK. Отличие OpenRebar, которое проверяемо: независимость от расчётной программы, сертификат As,prov ≥ As,req по ячейкам с полигонами дефицита, раскрой с учётом стыков, открытое офлайн-ядро с provenance и честными статусами (`Failed` не маскируется). Не заявлять: ML-модель (её нет), экономию стали в % (нет корпуса), «Revit-ready» для гнутых стержней.
