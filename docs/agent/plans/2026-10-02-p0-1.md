# P0-1′ — CI целиком зелёный

Дата: 2026-10-02. Ветка не создаётся, пока нет команды на коммит.

## Цель

Прогон на `main` не должен краснеть из-за пути к сборке, отсутствующего корпуса и CUDA-хэша. Тест корпуса при `OPENREBAR_REQUIRE_BATCH_CORPUS=1` по-прежнему падает без манифеста.

## Причина шага benchmark

Solution `Release|x64` собирается как Any CPU в `bin/Release/net8.0`. Команда `dotnet test <csproj> --no-build -p:Platform=x64` ищет `bin/x64/Release/net8.0`. На Ubuntu этого каталога нет, vstest завершается за ~1 с. То же у `dotnet publish --no-build -p:Platform=x64`.

Локально каталог `bin/x64` уже есть от прямой сборки проекта, поэтому ошибка видна в логе прогона `36911012627`, а не на этой машине.

## Файлы

- `.github/workflows/ci.yml` — снять `-p:Platform=x64` с `--no-build` на csproj (benchmark, publish, corpus). Корпус: `workflow_dispatch` и понедельник 03:00 UTC; на push/PR шаг `corpus: NotEvaluated`. Секрет `OPENREBAR_BATCH_CORPUS_ROOT` включает жёсткий прогон.
- `README.md`, `README.ru.md` — Quick Start с `-p:Platform=x64` на restore, build и test. Абзац про корпус совпадает с workflow.
- `ml/requirements.in` — CPU-колёса `torch==2.11.0+cpu`, `torchvision==0.26.0+cpu`, без `cuda-toolkit` и nvidia/triton.
- `ml/requirements.locked.txt` — пересборка с хэшами под manylinux cp311.
- `CHANGELOG.md`, шапки r5/r6, этот план.

## Риски

- Lock, собранный не на Ubuntu, может не содержать linux-хэшей. Компиляция идёт с `--platform manylinux_2_28_x86_64` и `--python-version 3.11`.
- `continue-on-error` не используется. Тест корпуса не удаляется и не ослабляется.
- Rs, края плиты и архив документов в эту задачу не входят.
