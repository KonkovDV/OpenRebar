# P1-1 — net8 и net10, две сборки Revit

Дата: 2026-10-02.

## Цель

Ядро (`Domain`, `Application`, `Infrastructure`) собирается как `net8.0;net10.0`. CLI — `net10.0`. Плагин Revit — две сборки по рантайму, не по году версии: `RevitNet8` (`net8.0-windows`) и `RevitNet10` (`net10.0-windows`). После 10.11.2026 `net8.0` остаётся только для Revit, который не получил обновление на .NET 10. Срок пересмотра — 01.06.2027.

## Цитаты (доступ 2026-10-02)

- Mikako Harada, 29.04.2026, [Revit 2026/2025 migration to .NET 10](https://blog.autodesk.io/call-for-preview-testing-revit-2026-2025-migration-to-net-10/): Revit 2025 и 2026 собраны на .NET 8; поддержка .NET 8 у Microsoft заканчивается 10.11.2026; Autodesk переводит две предыдущие версии Revit на .NET 10. Большинство надстроек продолжают работать; сложные случаи с нативным кодом могут потребовать перекомпиляции.
- Madhukar Moogala, 24.07.2026, [Autodesk Desktop Products 2025/2026: .NET 10 Updates](https://blog.autodesk.io/autodesk-desktop-products-2025-2026-net-10-updates/): «There are no API changes in any of these products as part of this update. The only change is that the underlying .NET runtime is moving from .NET 8 to .NET 10.» Revit 2026.5 целился на первую неделю августа 2026, линейка 2025 — на вторую неделю сентября. Надстройку, которую задевают ломающие изменения рантайма, нужно пересобрать под .NET 10.

Вывод, не цитата: российские установки с марта 2024, скорее всего, не получат эти обновления, поэтому сборка `net8.0-windows` для них нужна дольше.

## Файлы

- `*.csproj` ядра, CLI, тестов, плагина.
- `src/OpenRebar.RevitPlugin/addin/RevitNet8` и `RevitNet10`.
- `RevitRuntimeSelector`: major ≥ 10 → `RevitNet10`, иначе `RevitNet8`.
- `RELEASE_POLICY.md`, CI (SDK 8 и 10, тесты ядра на обоих TFM, сравнение хэшей).
- README, CHANGELOG, хвост r7 и §6.0 r5.

Тонкий загрузчик внутри Revit не собирается: в репозитории нет ссылки на Revit API, а файл `.addin` не умеет ветвиться по `Environment.Version`. Установка — две папки. Селектор фиксирует правило, которым загрузчик пользовался бы.

## Тесты

- Селектор и оба манифеста.
- `dotnet test` решения с `-f net8.0` плюс `Application.Tests` на `net10.0` (CLI только net10, поэтому эти тесты не входят в прогон net8). Счётчик README — сумма этих двух прогонов.
- Отдельный прогон Domain, Infrastructure и TestCorpus на `net10.0`.
- Хэши корпуса A0 и ведомости на net8 и net10 совпадают. Скрипт сравнивает файлы между собой, без константы, завязанной на ОС.

## Риски

SDK 8 не компилирует `net10.0`, поэтому в CI ставятся оба SDK. Одна DLL `net10.0` на все Revit не кладётся. API, которого нет в net8, в общее ядро не добавляется. r7 не требует self-contained CLI; публикация остаётся framework-dependent на net10.
