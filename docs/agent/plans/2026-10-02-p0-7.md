# P0-7 — Application на net8 и хэши эталонов

Дата: 2026-10-02.

## Цель

`RevitNet8` грузит `Application` как `net8.0`. Этот набор тестов должен собираться и проходить на `net8.0` и `net10.0`. CLI остаётся `net10.0`. Тесты, которые вызывают `Program.Main`, переезжают в `OpenRebar.Cli.Tests`.

Хэши `result.json`, `schedule.csv` и `reinforcement.ifc` для всех каталогов `examples/*` сравниваются между TFM. Время и пути в отчёте нормализуются. Из IFC убираются `IfcOwnerHistory`, метки времени и GlobalId.

## Файлы

- `tests/OpenRebar.Application.Tests` — `net8.0;net10.0`, без ссылки на CLI.
- `tests/OpenRebar.Cli.Tests` — `net10.0`.
- `tests/OpenRebar.Application.Tests/ExampleArtifactHashTests.cs`
- `tools/ci/compare_tfm_hashes.py` — обязательный список `.sha256`.
- `.github/workflows/ci.yml` — считаемый прогон Application на net8, Cli.Tests на net10, повтор Application на net10.
- `docs/VALIDATION_BASELINE.md` — как складывается счётчик.
- README и README.ru.

## Счётчик

В README входит сумма `test-results.trx` из шага Test: Domain, Infrastructure и TestCorpus на net8, Application на net8, Cli.Tests на net10. Повтор тех же библиотек на net10 пишет `tfm-net10-results.trx` и в сумму не входит.

## Описание репозитория

Владелец ставит в настройках GitHub: `Reinforcement layouts for flat RC slabs. .NET 8 / .NET 10.`

## Риски

Полный `result.json` может разойтись между рантаймами на формате чисел. Тогда хэш не подгонять округлением: показать дифф.
