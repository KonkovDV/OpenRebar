# P0-r9d — draw the hook that the schedule already counts

Date: 2026-10-03. Base: `main` at `faa52db`.

## What is wrong

`RevitRebarPlacer` drops every bar whose shape is not straight. The schedule and IFC still contain those hooks, so the model and the schedule disagree.

PR #157 does not fix this. Its `CompanyProfile.cs` and `IRevitPlacer.cs` were stored as one base64 line, so the build fails. It also sets the straight tail to 12 diameters and cites SP 63 clause 10.4.3. That length is not the default in this repository. r9 says `hooks.tailDiameters` stays 0, with `source: default`, until an owner sets it. Clause 10.3.33, already in `BendRules`, adds the centerline arc and no straight tail.

## What this change does

- `HooksProfile.TailDiameters` defaults to 0. A profile may set a larger multiple. A negative value is rejected. `generic.json` is unchanged, so example profile hashes stay put.
- `HookCenterline` builds the curve in millimetres. A hook is a semicircle of the centerline radius (`inner radius + d/2`) bending into the slab: up from a bottom bar, down from a top bar. The straight tail is added only when the multiple is above 0, and it continues the arc tangent, parallel to the bar.
- The Revit placer sends that chain to `CreateFromCurves`. With the default tail the chain is arc + line + arc. L and U bars are still not drawn; the placer records a warning and leaves them in the schedule and IFC.
- Cut length stays `clear span + bend arc`. The tail is not added to `TotalLength`, so the simple-slab figures do not move.

## Not in this change

U-bar generation, a quoted tail length, and Revit geometry for L and U.
